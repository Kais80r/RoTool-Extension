# RoTool

RoTool adds its own hammer-and-Roblox button directly beside Roblox's Settings gear in the top navigation. The button opens a Roblox-style **RoTool Settings** screen where **Sidebar Customization**, **Quick Settings**, **Best Friends**, **Friend Lists & Filters**, **RoTool Update Popups**, **Quick Play & Servers**, **Experience Places**, **Player Counts (CCU)**, **CCU Hover Graph**, **Game Events**, **Join Scheduler**, **Server History**, and **Copy Roblox IDs** can each be enabled or disabled independently. Features with finer controls have an accessible expandable section beneath their main switch. Existing interface features and advanced **Show** switches start enabled; the activity-recording **Server History** feature is an explicit opt-in and starts off. Changes apply immediately, stay synchronized across open Roblox tabs, and are saved locally in extension storage; disabling a feature does not erase its advanced choices, saved shortcuts, Best Friends selection, tracked Event games, or locally retained Server History. **Reset defaults** restores that same privacy-conscious default: existing interface features on and Server History off.

This unpacked Chrome/Edge extension adds an **Add shortcut** row beneath Roblox's normal left-navigation links and immediately above any promotional card. The row is cloned from the live Roblox sidebar, so it inherits the current row height, padding, typography, hover behavior, theme, zoom, and layout experiment; RoTool supplies its own thin plus so a changed native icon cannot leak into the clone. It supports both the redesigned `#left-navigation-container` sidebar and the older `.left-col-list` layout.

Expand **Advanced** beneath **Sidebar Customization** to control RoTool's **Events**, **Join Scheduler**, **Server History**, and **Custom Shortcuts** rows plus each standard Roblox sidebar row separately: Home, Profile, Roblox Plus, Messages, Friends, Avatar, Inventory, Trade, Communities, Blog, Official Store, and Buy Gift Cards. **Show all** and **Hide all** update the whole group in one action. Every switch defaults on. Hidden rows are marked rather than removed or replaced, so enabling one restores the same live control and its behavior. RoTool does not change RoPro-owned sidebar rows such as Themes. These choices are local and reversible, do not block their destinations or alter account data, and do not hide matching links elsewhere such as the footer. Turning the Sidebar Customization master switch off restores every Roblox row and removes RoTool's custom rows while temporarily disabling its advanced controls without forgetting individual choices.

**Game Events** adds a fixed **Events** calendar button to the sidebar. It opens one extra-wide scrolling feed for official Roblox events published publicly through Experience Events by games the user chooses. Up to 30 games can be tracked for each of up to eight recently used Roblox accounts on this device by searching Roblox's public experience results or entering a game URL, Place or Universe ID, or name. The default **All** view keeps currently active events together in a compact **Live Now** area at the top, then starts one uninterrupted upcoming-event timeline underneath it; **Live** and **Upcoming** can show either part alone. **Hide** collapses only the active-event cards for the current window and becomes **Show**, while the live heading, count, and upcoming timeline remain visible. Upcoming events are labeled **Today**, **Tomorrow**, a nearby weekday, or a full later date. Farther-away starts receive more vertical space than nearby starts, with a cap so long waits do not create enormous blank areas. A solid green **Now** point represents the current time and moves toward the next event on that upcoming axis, while hollow points mark scheduled starts. Live cards do not use their old start dates as timeline gaps, and event rows use spacing instead of horizontal divider lines. Rows keep a simple hierarchy with the raw event title, game name, thumbnail, a compact start countdown for upcoming events or end countdown for live events, plus explicit **Join Game** and **View Event** actions. **Join Game** hands that event's public Place ID to Roblox's launcher only after the user clicks it; **View Event** opens Roblox's event page. Roblox's raw subtitle remains available in the title tooltip and to screen readers without crowding the visible row. **Manage Tracked Games** opens the local tracked-games controls without affecting Roblox favorites.

The Game Events dashboard fetches only when its window opens, after a game is added, or when **Refresh** is chosen; its tracked feed does not poll in the background, RSVP, send notifications, or keep an archive. Separately, when Join Scheduler is enabled on a Roblox game page, RoTool validates the page's rendered upcoming event cards against Roblox's credential-free public event data. A successful result is checked again after about ten minutes while the page remains open, and failed validation leaves the RoTool control hidden. Only a verified future card receives **Schedule with RoTool**; choosing it opens the same in-page Scheduler with public event details prefilled, and nothing is saved or armed without the user's explicit final confirmation. RoTool shows only live and upcoming events officially published through Roblox, not private in-game countdowns, social posts, or Discord announcements. Roblox's public Experience Events endpoint is undocumented and can be unavailable, rate-limited, or changed. RoTool therefore labels partial or saved results truthfully and fails without inventing event data. Event favorites stay in extension storage for the current Roblox account, and no list is uploaded to a RoTool service.

**Experience Places** adds a responsive square-card row immediately before Events on eligible experience pages, with a verified after-About fallback for supported layouts that do not render Events. RoTool first verifies the current Place-to-Universe mapping and checks public Games metadata with credentials omitted; it proceeds only when the IDs agree and Roblox explicitly says the experience is not content-restricted. It then requests that Universe's Roblox-listed Place list directly from Roblox's official Develop API with account credentials omitted, reveals large lists in small steps, and uses Roblox's direct Place-icon thumbnails so different subplaces remain distinguishable. **Main place** marks the Universe's root Place, while **Current** is appended when that card is the page being viewed. Cards only open normal Roblox Place pages; RoTool does not add a subplace launch action, because some subplaces can be entered only from inside the experience. Roblox may redirect an internal Place page back to the experience's Main place when that subplace is not directly accessible. The feature starts enabled and can be turned off independently in RoTool Settings.

**Join Scheduler** opens as a Roblox-style RoTool dialog on the current Roblox page for one-time reminders and scheduled launch attempts. It matches the desktop size of RoTool Settings and becomes a near-fullscreen dialog on smaller screens. Its inert packaged form and styles are mounted in a closed shadow tree to avoid CSS collisions with Roblox; this is UI isolation, not a security boundary against another installed extension with the same Roblox-page access. Nothing is scheduled automatically when the feature is installed or enabled. The user chooses an exact game, local date and time, **Notify me** or **Auto-join**, and either the public game or a saved official Roblox private-server link. **Notify me** is the default. **Auto-join** additionally requires a fresh acknowledgement of the exact game, time, destination, one-attempt behavior, and whether RoTool may switch away from another game. Public and private destinations never fall back to one another. A schedule can also be opened prefilled from an upcoming official Game Event; if Roblox moves that event's published start time, the automatic schedule is disarmed instead of silently reusing old consent.

Both scheduler modes request the browser's optional notification permission only from the explicit **Schedule** click. A warning appears 30 seconds before the due time with the game's public Roblox icon when available and user controls to join or cancel; the packaged RoTool icon remains the safe fallback. An armed Auto-join then makes at most one launch attempt at the agreed time. RoTool cannot wake a sleeping computer, start a fully closed browser, guarantee that Roblox accepts an external launch, guarantee server capacity, or confirm that the player arrived. A materially late alarm becomes **Missed** and requires another user action rather than unexpectedly moving the player after wake or restart. Revoking notification permission, disabling Join Scheduler, changing accounts, canceling the schedule, deleting its private destination, a canceled or moved official event, or an unresolved schedule collision prevents the automatic launch.

Private-server destinations are accepted only from tightly validated official HTTPS Roblox links and are saved per Roblox account in extension-owned IndexedDB. Legacy links are checked against their Place and Universe; modern opaque Roblox share links are clearly labeled when Roblox cannot confirm the game and require explicit unverified-link confirmation. The password-style field is cleared immediately after **Check Link** or **Schedule**; RoTool does not redisplay the raw link or access code, return it in scheduler responses, show it in notifications, log it, send it to a RoTool or unrelated service, or use it as a silent public fallback. Roblox receives the official link or code when needed for validation and launch. At launch, a legacy access code is passed transiently and directly from the background worker into Roblox's own private-server launcher; a modern Roblox share URL is opened on Roblox and may appear in the browser address bar and history. The scheduler otherwise shows only masked state such as **Private server saved**. Another browser extension that the user has also allowed to read Roblox pages may be able to inspect page inputs while they are being typed; RoTool cannot create a security boundary against an extension with the same browser access. This local browser-profile storage is not an encrypted password vault, so anyone who can inspect that profile's extension data may also be able to recover a saved bearer link; remove it when it is no longer needed.

**Server History** is an explicit opt-in feature and is off by default. Once enabled, its fixed sidebar button opens a large local history window showing only the latest 30 server sessions observed for the current Roblox account on this device. The feature remains independent of saved custom shortcuts: its advanced **Server History** sidebar switch can hide the button without clearing saved sessions or stopping collection, while turning the Server History feature itself off stops collection and closes its window. **Clear history** requires confirmation and removes that account's locally saved entries.

Server History observes the signed-in account's Roblox presence roughly once per minute. Because a browser extension cannot receive exact Roblox-client join and leave events, the saved first- and last-seen times and observed duration are approximate, and short sessions or changes while the browser worker is asleep can be missed. Sessions are grouped by their last-observed local date as **Today**, **Yesterday**, a recent weekday, or a full older date. Each compact card shows the observed start, end, and duration plus **View Game** and **Rejoin Server** actions. **View Game** opens that experience's Roblox page. RoTool does not pre-check status or player count; an explicit Rejoin passes the exact saved Job ID directly to Roblox's instance launcher, which makes the real availability and access decision. Game metadata requests use Roblox's current page language, with English as the safe fallback, so Server History names and times follow the Roblox site instead of the computer's locale. Exact server Job IDs stay out of the dialog and DOM and remain background-owned until Rejoin; viewer account IDs remain background-only. The dialog receives public experience and Place metadata for links and thumbnails plus an opaque RoTool session key for rejoin and clear actions. No Server History data is uploaded.

Clicking it opens a Roblox Foundation-style modal where you can add secure `https://` links. The modal inherits Roblox's current light or dark theme, surface, spacing, close affordance, and standard/emphasis button styling while retaining native keyboard and Escape behavior. Saved shortcuts appear immediately above the Add shortcut row and are stored only in the browser's local extension storage.

Profile, experience, and community links automatically use their real Roblox avatar, game icon, or group icon. Other Roblox pages use a matching built-in symbol, and external websites use a globe fallback.

The **Your shortcuts** list supports drag-and-drop reordering as well as keyboard-friendly up/down buttons. Changes are saved immediately and reflected in the sidebar.

On Roblox experience cards, RoTool adds a bottom action tray that rises over the thumbnail on hover or keyboard focus. Expand **Advanced** beneath **Quick Play & Servers** to show or hide **Quick Play**, **Private Servers**, and **Random Server** independently; all three Show switches default on. The master switch temporarily disables the entire tray without changing those individual choices, and disabling all three actions leaves no empty tray. A disabled Private Servers action also prevents its capability check from being started. It supports Roblox's small square cards, wide featured cards, and large landscape cards without putting buttons inside the card's navigation link. When Private Servers is enabled, its capability check begins only when that card is hovered or receives keyboard focus, so loading or scrolling through a large page does not spend Roblox's lookup quota. After Roblox explicitly confirms that an experience supports private servers, cards at least 144 CSS pixels wide show **Private Servers** on the left, a wider primary **Quick Play** in the center, and **Random Server** on the right when those actions are enabled. Unknown, failed, or unsupported capability checks keep the private-server control hidden instead of guessing; a failed check remains unknown and can be retried by hovering or focusing the card again. Confirmed results survive card remounts, page reloads, extension-worker suspension, and RoTool updates. A background-wide queue paces user-initiated checks across every RoTool tab, immediately serves a saved result while it is being refreshed, and prioritizes never-checked games over those background refreshes. It reads Roblox's rate-limit reset headers, keeps still-pending cards in that queue during the cooldown instead of falsely completing them as unsupported, and automatically resumes them when Roblox's quota resets. A ResizeObserver keeps the control layout synchronized when Roblox resizes cards without a DOM mutation. Wide controls use their larger scale from 172 CSS pixels upward; narrower landscape cards keep the compact scale instead of losing Private Servers. Quick Play uses Roblox's native play-button classes and a centered play glyph at a proportionally smaller size. Private Servers opens an accessible Roblox-style dialog containing the private servers returned by Roblox for the signed-in account, with the experience icon and current game-wide creation price in its header, each owner's avatar beside their server, guarded automatic pagination, and a Join button for each non-full server. Roblox can return a server even when its owner-level permissions later reject the viewer, because the list does not provide RoTool a definitive per-viewer permission result. A full-width local search filters the loaded list by server name, owner display name, username, owner ID, or server ID without making requests as the user types. The linked experience name opens its game page, and every owner with a public user ID links to their profile. Rows render progressively while remaining pages and public thumbnails fill in. Full servers remain visible with a disabled **Full** button. If Roblox reports that the whole account is restricted from joining, that restriction remains active across every loaded page and disables the server actions. An always-visible **View Private Servers** button stays at the far left of the footer and opens the experience's normal Roblox server page, including when Roblox returns no servers. Unsupported experiences and cards that cannot safely fit three controls retain the available enabled actions that fit safely.

**Player Counts (CCU)** is a separate feature from Quick Play. It adds Roblox's playing-count icon and current concurrent-user count to wide experience cards that do not already have one. RoTool uses the Universe ID already present in Roblox's card link whenever available, groups up to 50 missing cards into each public Games metadata request, and continues through every group until all missing wide cards are covered. Results are cached briefly and revalidated before rendering so recycled tiles cannot receive another game's count. Compact values use a stable decimal point (`5.3K`). Editorial cards place a native-shaped rating and player count at the top right beneath the thumbnail so descriptions retain their own line; ratings are requested in one public batch only for cards that do not already show one. Sponsored tiles keep Roblox's **Ad** disclosure while displaying the compact native pattern `Ad • 91%` without the redundant word “Rating.” Compact cards keep Roblox's existing statistics. If Roblox or BTRoblox already supplies a playing-count icon or value on a wide card, that metadata remains authoritative: RoTool neither changes it nor requests or renders a duplicate.

While CCU Hover Graph is enabled, RoTool takes one local snapshot of Roblox Charts approximately every five minutes. The background worker requests Charts with the browser's existing Roblox sign-in, so eligible experiences—including account/context-dependent and 16+ listings—can be collected without keeping a Charts page open. Each sweep merges four Chart pools—Roblox's selected local location and **All Locations**, each for **Computer** and **All Devices**—follows every returned overview page, and deduplicates repeated appearances by Universe ID. The local location is selected by Roblox rather than hardcoded by RoTool. The Chart responses already include each listed experience's CCU, so RoTool does not request every game separately. If a signed-in Chart request is unavailable, that pool safely falls back to Roblox's anonymous public response; a rate limit is honored rather than retried anonymously. A real Chart card missing from the current snapshot can still request one immediate public Universe CCU observation from a validated top-frame Charts route, but this is only a fallback and is not required for normal background tracking. Home and other pages cannot seed history. Holding the pointer over a player count for a tenth of a second opens a compact interactive graph centered beneath that game's thumbnail. It floats over the title and rows below instead of moving the page, follows remounted Roblox tiles, and flips above the thumbnail only when the viewport has no room beneath it; keyboard focus opens it immediately. The graph represents a rolling twelve-hour window while retaining up to seven days locally, shows the exact latest stored value (for example `930.925`), its saved freshness, a signed change such as `+0.4%` or `−0.2%`, the duration of that directional run, and labeled CCU and locale-aware time axes. Its thin line uses green rising, red falling, and gray flat edges between consecutive five-minute observations; adjacent same-direction edges share one rounded-join run so the graph looks continuous without inventing values between samples. Leading, internal, and trailing periods without a saved observation use clearly marked amber hatching, so the graph never stretches data across time RoTool did not record or confuses missing history with a falling red line. Moving over the plot reveals a crosshair with the exact stored count and time; its tooltip stays inside the graph, while a hatched interval instead reports that no observation was stored. Keyboard users can enter the plot with Arrow Down or F2 and inspect stored points with the arrow, Home, and End keys. The percentage covers the latest uninterrupted directional run visible in the twelve-hour window; a reversal, no-data gap, or the window boundary resets the baseline. Its accessible explanation gives the exact baseline, latest count, and stored elapsed time. A neutral dash appears when there is no valid comparison or the baseline count is zero. Empty visible history is not cached, and an open missing or one-point graph retries after the next snapshot. It clearly reports when no observations exist in the last twelve hours. A new installation needs two snapshots, normally about five minutes apart, before it can draw its first line.

Random Server uses a three-tier server-and-die icon and chooses a random validated non-full public instance from up to 100 servers returned by Roblox. It requests the server list only after a real click, briefly caches validated candidates to reduce rate-limit pressure, then joins through Roblox's own instance launcher. The public server list does not expose reliable player identities, so Random Server cannot guarantee that no friend is present. RoTool does not duplicate or alter RoPro's controls when RoPro's **Experience Quick Play** feature is enabled, so disable that RoPro setting to use RoTool's tray on the same cards.

On Roblox **Home**, RoTool places **Quick Settings** above Best Friends as a compact settings stack anchored to the left instead of filling the Home width. **Online Status**, **Current Experience**, and **Inventory Visibility** are separate controls backed by Roblox's real account-specific choices. Expand **Advanced** beneath Quick Settings to show or hide them independently; all three controls default on, and hiding every control removes the whole Home card and skips its Roblox settings request. The master switch temporarily disables the card without forgetting those individual choices. Roblox can automatically change Current Experience to the matching audience whenever Online Status changes—not only when it becomes **No one**. RoTool captures the exact live Current Experience choice, changes Online Status first, refreshes Roblox's newly available options, and restores the previous Experience choice whenever Roblox still permits it, including when the Current Experience row itself is hidden. When RoTool sets Online Status to **No one**, it arms a single-use, account-specific restore record because Roblox temporarily locks Current Experience; that record expires after 24 hours and is consumed when Online Status is enabled again. RoTool does not infer intent from a generic previously observed value, and it never guesses or broadens privacy when no valid record exists. Age, region, verification, and parental-control restrictions remain authoritative. Changes keep the previous value visible while Roblox processes them, are serialized, checked against fresh server snapshots, and appear as saved only after Roblox confirms them. Status notices use their own full-width line instead of competing with the header actions. **Hide** minimizes the card to its header and becomes **Show**; the header keeps the same top position and this layout choice persists without disabling the feature. Other privacy controls remain available through **More Settings**, which opens Roblox's full Privacy page.

On Roblox **Home**, RoTool adds a **Best Friends** carousel immediately above the normal Friends carousel. It clones and measures Roblox's live carousel so the tile spacing, avatars, presence badges, and experience labels follow the current Home design. Empty layout space can be reused, but real Roblox banners and cards stay above both friend rows instead of separating them. When a clear compact space exists beside a right-side widget such as RoPro's Most Played panel, RoTool lifts only Quick Settings into that space. Best Friends stays in normal full-width flow below the widget, so its header, actions, and friend tiles are never narrowed or covered. If the complete Quick Settings card cannot fit safely, the whole stack remains in normal flow. An established placement is frozen while a RoTool modal is open and measured again after it closes, preventing the Add Best Friend, shortcut, and private-server dialogs from causing a down/up flicker. Best Friends are displayed with people in an experience first, then online people, then offline people; the saved selection order remains stable within each presence group. Their labels reuse Roblox's native inner text lane, so long display names and experience titles truncate at the same width as normal Friends; Verified and Roblox Plus badges remain fixed beside the shortened name in Roblox's order. Hovering a Best Friend opens immediately using Roblox's current popup structure, typography, colors, spacing, and action icons. Friends in an experience get a preloaded WebP game icon plus **Join** and **View Profile**; **Chat** is included only when Roblox reports that app chat is enabled for the signed-in account. Other friends use Roblox's compact action menu under the same rule. The popup is centered on the visible avatar and meets the bottom of the labels like Roblox's own menu instead of being offset by extra carousel height. **Add Best Friend** and **Manage** open a searchable Roblox-style picker containing the signed-in account's complete current friend list, including accounts beyond Roblox's 200-friend legacy response limit. Search matches either display name or username and accepts an optional leading `@`. The picker becomes usable from the base friend snapshot before decorative names and avatar thumbnails finish enriching, and Friends requests have a bounded timeout instead of leaving the UI loading forever. **See All** opens the Friends page with the Best Friends filter selected. Selections support up to 100 people and are stored separately for each signed-in Roblox account in local extension storage. A saved person who is no longer a current friend is removed automatically the next time the row loads.

On the Roblox **Friends** page, RoTool replaces Roblox's broken **All** result with a complete custom list while reusing Roblox's existing All pill; no duplicate All button is added. It also adds adjacent **Online (total)**, **Offline (total)**, and **Best Friends (total)** pills beside **All** and **Trusted**. RoTool follows Roblox's authenticated cursor pagination through the complete friend list, preserves that order across online and offline people, and merges immediately available profile names from the legacy response without ever treating its 200-friend limit as a complete total. It checks presence in safe concurrent batches and renders the base list before decorative names and lazy avatar thumbnails finish enriching. Search covers every rendered friend by display name or username, including queries beginning with `@`. Best Friends retains its selected order. Roblox's native list and pagination stay hidden while All or another RoTool filter is active; clicking **Trusted** restores Roblox's native Trusted view and controls.

The same page has one compact **Filters** button that opens a small Roblox-style window anchored beneath it, without dimming or blocking the page. Its safe filters include Roblox's public **Verified** badge; **Roblox Plus**; any combination of **In experience**, **Online**, **Offline**, and **In Studio** status; a specific experience; and **Best Friends only** or **Exclude Best Friends**. Selected statuses form a union, while the different filter sections combine with AND. Applying advanced filters switches to the complete **All** list first so an Online or Best Friends tab cannot silently hide otherwise valid matches. Local sorting supports display name or username A-Z/Z-A plus In experience, Online, Offline, Best Friends, or Verified first. Type an experience name normally; Roblox game links, Place IDs, and Universe IDs also remain accepted. The `?` explanation identifies presence results Roblox could not confirm; unchecked people are never reported as false matches. Only confirmed matches appear in the filtered grid.

Applying Roblox Plus, status, Best Friends, and sorting options uses data RoTool already loaded and does not request information separately for every friend. A specific experience needs only its game target resolved. RoTool intentionally does not offer social-count sorting, relationship-graph scans, or true Recently Online because those require expensive or unreliable requests. RoTool does not upload or persist a copied social graph to any third-party service.

Right-clicking a supported Roblox page, link, or linked image adds commands to Chrome or Edge's normal context menu. The menu uses RoTool's transparent black Roblox mark with a white foreground hammer rather than the generic puzzle-piece icon. Supported values include User, Place, Universe, Asset, Texture, Community, Community Role, Bundle, Badge, Game Pass, Outfit, Developer Product, and Experience Subscription IDs. Animation, audio, model, mesh, image, plugin, and clothing pages use their common Roblox **Asset ID** rather than duplicate type-specific labels.

When exactly one ID applies, Chrome or Edge shows that command directly in the normal right-click menu. Asset pages use the descriptive **Copy Texture ID / Asset ID** parent with two separate choices. Other pages with multiple applicable IDs are automatically grouped by the browser beneath the RoTool icon. This means a community page gets a direct **Copy Community ID**, while a normal experience gets separate **Copy Place ID** and **Copy Universe ID** choices in the browser's automatic submenu.

Decals and other assets expose separate **Copy Texture ID** and **Copy Asset ID** commands. They work on asset detail pages and linked pictures in Roblox's catalog, library, Creator Store, Creator Marketplace, and Creator Dashboard routes such as `/dashboard/creations/store/{assetId}/configure`. Texture lookup uses Roblox's authenticated current Asset Delivery API and can therefore resolve private assets that the signed-in account is allowed to access. A brief message on the page confirms what was copied or explains why Roblox could not provide the requested value.

Creator Dashboard experience pages also keep their IDs distinct. An experience overview exposes its Universe ID directly. Nested place, badge, pass, developer-product, and experience-subscription pages expose the Universe ID plus that resource's own ID. User outfit pages similarly expose both User and Outfit IDs. Private-server codes, share codes, server-instance IDs, authentication values, and unrelated numeric URL values are deliberately ignored.

A Roblox experience has both a **Place ID** and a **Universe ID**. The number in a normal `/games/...` URL is the Place ID; Roblox also calls the containing Universe ID the game's ID in some APIs and tools. The extension labels both so they are not confused.

A decal's catalog **Asset ID** is not necessarily the same as the underlying **Texture/Image ID** used by an image property. Likewise, classic clothing can reference a separate template. The extension labels a Texture, Image, or Template ID only after verifying that relationship through Roblox's asset metadata and delivery response; it does not guess from a thumbnail URL.

The Home **Best Friends** header includes a compact **Hide** control immediately after `Best Friends (N)`. It collapses only the people row and becomes **Show**; **Manage** and **See All** remain available, loaded tiles are preserved, and the preference persists across reloads.

Roblox's normal Home **Friends** header gets the same compact **Hide**/**Show** control immediately after `Friends (N)`. It hides only Roblox's people row, releases Roblox and BTRoblox's reserved carousel height so the content below moves up, keeps the original heading and **See All** action intact, preserves the loaded tiles and scroll state, and remembers its own independent preference across reloads.

**CCU Hover Graph** is independent from **Player Counts (CCU)**. It works with Roblox's own player counts, including counts on Recently Played cards, as well as counts added by RoTool. Turning Player Counts off removes only RoTool-added numbers; turning the graph off removes its hover/focus triggers and stops future background Chart snapshots without deleting saved history.

## Install for testing

For a first installation from GitHub Releases, download **`RoTool-setup.zip`**—not GitHub's automatically generated **Source code** archive and not either component-only ZIP. Extract it into a permanent folder, then load that extracted extension root below. Keeping that same folder and browser extension card preserves RoTool's local settings when using the included updater later.

### Chrome

1. Open `chrome://extensions`.
2. Turn on **Developer mode**.
3. Select **Load unpacked**.
4. Choose this extension folder.
5. Open or reload `https://www.roblox.com/home`.

### Microsoft Edge

1. Open `edge://extensions`.
2. Turn on **Developer mode**.
3. Select **Load unpacked**.
4. Choose this extension folder.
5. Open or reload `https://www.roblox.com/home`.

## Maintaining releases

Maintainers create a release by bumping `manifest.json` and pushing the matching tag, such as `v0.16.27`. The GitHub workflow runs every test, builds the strict 21-file `RoTool-extension.zip`, the exact three-file `RoTool-updater.zip`, and the initial `RoTool-setup.zip`, publishes a SHA-256 file for each, and creates the release. Any change to an updater-core file must also increase `$script:UpdaterVersion`; a release with different core bytes but the same updater version is rejected. Configure a real `OWNER/REPOSITORY` when building locally or let GitHub Actions use the repository automatically. Never put a GitHub token, private signing key, browser profile, or local updater configuration in the repository.

## Permissions and safety

- Its sidebar and friends features run only on `https://www.roblox.com/*`. The small copy-and-notification helper also runs on Roblox's Creator Store and Creator Dashboard at `https://create.roblox.com/*`.
- Game Events stores up to 30 tracked games locally for each of up to eight recently used Roblox accounts. Those favorites contain only public game IDs, names, and the time they were added; they are not Roblox favorites and are not uploaded.
- Uses `storage` for your RoTool feature and advanced visibility switches, the Quick Settings, Best Friends, and normal Home Friends minimized states, the per-account remembered Current Experience choice, the shortcuts you create, ordered Best Friends user IDs, and—only after you opt in—the latest 30 Server History observations for up to eight recently used signed-in Roblox accounts. Join Scheduler separately uses extension-owned IndexedDB for bounded, per-account one-time schedules and private destinations so bearer links never need to enter content-page storage.
- Uses `contextMenus` to add the Roblox ID copy commands and `clipboardWrite` only after you choose one of them.
- Uses only Roblox's official Users, Friends, Presence, Profile, Thumbnail, chat-metadata, and User Settings endpoints to assemble its account features and to match Roblox's own availability rules.
- Quick Settings reads the current account-specific options only on Home, when **Refresh** is chosen, and before or after a requested change. It never polls them. A change is accepted only from RoTool's top-frame Home controls and is limited to Roblox-returned allowlisted options. Online Status and Current Experience are always sent as separate single-setting writes. After any Online Status change, RoTool fetches the resulting Experience options before restoring the exact previous choice; if Roblox no longer offers it, RoTool displays Roblox's confirmed current value instead of guessing. The required CSRF token stays only in the extension worker's memory and is never returned to the page, stored, or logged.
- Uses Roblox's public Games server-list endpoint only when **Random Server** is clicked. Random Server validates non-full Job IDs and briefly caches candidates; Server History does not scan that list or request server player counts.
- The Game Events dashboard reads Roblox's public Experience Events endpoint at `apis.roblox.com` only when its window opens, after a game is added, or when **Refresh** is chosen. Dashboard requests carry the Roblox page language but omit account credentials; a separate signed-in viewer check selects the correct local favorites. A short in-memory cache reduces repeated reads, and partial failures can reuse cached results without creating a persistent event archive. Independently, an exact Roblox game-detail page may send its public Place ID and up to 50 rendered event IDs present in the page to the extension worker when Join Scheduler is enabled. The worker omits credentials, accepts only official upcoming matches for that game, and revalidates successful card data after about ten minutes; it returns only bounded public IDs, names, and times needed for the prefill. The feed's **Join Game** remains click-only, and **Schedule with RoTool** only opens a prefilled draft. Only the user's final confirmation can create a Join Scheduler record or authorize a later one-shot launch attempt.
- On an eligible exact Roblox game-detail page, **Experience Places** first verifies the current Place-to-Universe mapping and makes a public Games metadata request with credentials omitted. It requires the route Place, unique matching Universe/root Place, and `isContentRestricted` explicitly false to agree. It then makes a credentialless request to Roblox's public Develop API for that Universe. It validates every returned Place against the Universe, follows only opaque Roblox cursors after **Load more**, limits retained results, and never sends the list to a RoTool service. Direct Place-icon requests also omit credentials. Place cards are page links, not join controls.
- Join Scheduler asks for the optional `notifications` permission only after a trusted **Schedule** click in its Roblox-page dialog. The content script immediately relays that permission request to the background worker in the same user gesture; Chromium 102 or later is required for this optional-permission flow. It uses one coordinator alarm for the next due record rather than continuously polling. Scheduler cards and reminders request only the exact public Roblox game icon for the record's validated Universe ID, omit account credentials and referrers, and retain the letter or packaged RoTool fallback when the response is late, malformed, oversized, or unavailable. Every alarm, notification action, edit, cancellation, and launch is rechecked against the current signed-in Roblox account and current feature state. A durable one-shot claim prevents reloads, duplicate alarms, or concurrent requests from making repeated launch attempts. Clicking a reminder notification returns to the same in-page Scheduler in a normal Roblox tab. The extension does not ask for a permission that could wake a sleeping computer or closed browser, and it never treats a delayed alarm as permission for a surprise late launch.
- Player Counts reads public Games metadata, while CCU Hover Graph reads first-party Roblox Charts metadata. The browser attaches its normal Roblox sign-in to the fixed Charts endpoint so the background sweep matches account-eligible listings without requiring an open Charts tab; if that request is unavailable, RoTool falls back to the anonymous Chart pool. The extension has no `cookies` permission and never reads, stores, logs, or exports the Roblox cookie. Missing wide-card counts and ratings remain batched and briefly cached, while the local-location/All Locations and Computer/All Devices Chart combinations are sampled every five minutes into one compact deduplicated snapshot containing only Universe IDs, timestamps, and CCU values. Chart history is retained for up to seven days in extension-owned IndexedDB, repeated Chart placements share one Universe history, and no data is uploaded. Home recommendations are not tracked, and RoTool does not record which experiences you open or play while the separately disclosed, opt-in Server History feature is disabled. Turning CCU Hover Graph off stops the Chart collector without deleting the history already stored locally.
- Checks Roblox's public private-server product metadata without sending account cookies only after the user hovers or keyboard-focuses an experience card. Merely mounting, loading, or scrolling past cards performs no capability request. RoTool shows the control only after Roblox returns an explicit supported result. Ambiguous, failed, and rate-limited responses remain hidden and are never saved as unsupported. Confirmed supported/unsupported capability booleans, the public game-wide Robux price, and their public Place/Universe IDs are kept in bounded extension storage sized to retain large discovery pages without evict-and-recheck churn; supported results are fresh for 24 hours and recoverable for seven days while revalidation runs, while unsupported results are fresh for 30 minutes and recoverable for six hours. No private-server name, owner, access code, or membership is stored there. Saved results are returned immediately when the card is next hovered or focused, and a stale result polls only until its already-started background refresh is confirmed. Requests pass through a paced background-wide concurrency queue where never-seen games take priority over stale refreshes. When Roblox reports that its quota is nearly empty or exhausted, RoTool retains user-initiated queued checks, honors the reported reset time, retries the throttled check, and then continues without falsely marking a game unsupported. The authenticated private-server list is requested only after **Private Servers** is clicked and follows every guarded cursor page automatically. Roblox's list may include servers whose owner-level settings ultimately reject the viewer; RoTool does not claim that list inclusion proves access. That list and its access codes are kept in extension memory, are not persistently cached, are never included in the search index, and are discarded when the dialog closes.
- Uses Roblox's public, read-only Universe, Economy, and Asset Delivery lookups when a Place ID must be mapped to a Universe ID or an asset relationship must be verified. These lookups do not modify Roblox data.
- Roblox's own online-status privacy rules remain authoritative; friends whose status is hidden are not exposed by the extension.
- Best Friend Join and Chat use Roblox's own current page handlers only after a real click on the corresponding RoTool button. Chat is not rendered unless Roblox's current metadata says it is available. If Roblox does not expose a handler in the current page build, RoTool reports that the action is unavailable instead of guessing a launcher or chat URL.
- Quick Play, Private Servers, and Random Server read only the positive Place ID already present in a same-origin Roblox `/games/...` card link. They launch only after a real primary click, never store play activity, and never send a request to a RoTool server. For the card-based Private Servers feature, the isolated content script sends the selected access code directly to RoTool's background worker. The worker accepts it only from the top frame of an exact `https://www.roblox.com/*` page, then uses a minimal one-shot MAIN-world injection to call Roblox's existing `joinPrivateGame(placeId, accessCode, "")` launcher. That transient access code never passes through a page DOM event, appears in markup, enters persistent storage or logs, or gets exported. Join Scheduler likewise clears its password-style input promptly, sends a submitted link only through an extension runtime message to the background worker, and returns only masked destination metadata to the in-page dialog.
- Uses the `scripting` permission and the `https://www.roblox.com/*` host permission only for immediate user-triggered launches and explicitly consented one-shot Join Scheduler attempts. Private Servers passes the validated Place ID and access code to Roblox's existing private launcher. Server History passes its background-owned Place ID and exact Job ID to Roblox's existing `joinGameInstance` launcher; it deliberately has no inexact deep-link fallback. Join Scheduler passes only the already authorized public Place ID or background-owned private destination and never silently changes destination type. Each injection returns only a small attempt status; RoTool does not claim that status proves the client joined.
- Authenticated requests let the browser attach its normal Roblox cookie. The extension has no `cookies` permission and never reads, stores, logs, or exports `.ROBLOSECURITY`.
- Best Friends presence results, enriched names, and thumbnails stay in memory; only its selected user IDs are saved. Separately, opt-in Server History persists the signed-in account's latest 30 presence-derived Place/Universe/Job IDs, a bounded experience/location label, and first/last-observed times. It does not persist thumbnails, upload the records, or request/display friends' last-online history.
- Checks the fixed official GitHub Releases API without authentication and caches successful checks for 24 hours so Roblox can show a short update notice. After a failed check, it waits at least one hour before trying again; those network-check limits are independent of the reminder frequency. The request sends no Roblox cookies, account data, or GitHub token; RoTool does not download or run remote code. Update banners are eligible only while an active, visible tab is on the exact Roblox Home route, and leaving Home immediately removes the page copy. Game-page navigation never claims or shows a banner. **RoTool Update Popups** starts on and its **Reminder frequency** defaults to **Every 6 hours**; Advanced also offers **Every Home visit**, **Every 30 minutes**, **Every hour**, and **Every 24 hours**. Timed choices share one cooldown across tabs. **Every Home visit** can present each available version at most once during the current Home document/SPA visit; routine timers perform status-only checks and cannot repeat that version. Refreshing Home or leaving and later returning starts a new visit, while merely opening a game does not show another reminder. The dedicated versioned local preference synchronizes across tabs, remains saved while the parent switch is off, and returns to six hours with **Reset defaults**. Turning the parent switch off hides only the Home banner. RoTool Settings continues to show a known update on any Roblox page without consuming a reminder, and closing a banner removes only its current page copy.
- Accepts only `https://` links and rejects executable URL schemes such as `javascript:` and `data:`.
- Private-server URLs can contain access codes. The right-click feature deliberately ignores those codes, authentication tickets, server job IDs, cookies, and arbitrary query-string values.

## If the row does not match or appear

Roblox serves different layouts to different accounts and experiments. To provide the exact safe markup:

1. Right-click a normal inactive sidebar row, such as **Profile**, and select **Inspect**.
2. In the Elements panel, select the outer `<li>` containing that entire row.
3. Right-click it and choose **Copy > Copy outerHTML**.
4. Repeat for the immediate parent containing all sidebar rows.
5. Send those two snippets after removing any username or notification counts you do not want to share.

Do **not** send anything from DevTools' Application, Storage, Cookies, or Network panels. Never share a `.ROBLOSECURITY` value.
